# Spike 14 — embedding 编码器定维（关闭 R16）

**目标**：架构 §5 原写 `embedding vector(1024)` 是 spike 01 验证 DDL 可执行性的**占位**，与真实编码器
维度不符（nomic 768d / qwen3 4096d）。**换编码器 = 重建索引**，因此必须在 P1 迁移前定死编码器与维度。

本 spike **只定维度与选型**，不重复 spike 02/03 已做过的分流质量评测。

## 运行环境
- 本地 Ollama 0.33.3；已装 `nomic-embed-text:latest`(274MB)、`qwen3-embedding:latest`(4.7GB)。
- `probe_dim.py`：仅标准库；显式 `ProxyHandler({})` 绕过本机 Clash 代理（否则 localhost 挂起，见实施计划 §8.3）。
- 冷启动 = 首次调用含模型加载；预热后再测单条与批量 32 条。

```bash
python probe_dim.py   # → probe_result.json
```

## 结果（2026-10-31 实测，单次采样）

| 模型 | 维度 | L2 范数 | 冷启动 | 预热单条 | 批量 32 条 | 单条摊薄 |
|---|---|---|---|---|---|---|
| `nomic-embed-text:latest` | **768** | 1.0000 | 0.65 s | 0.012 s | 0.30 s | **9.5 ms** |
| `qwen3-embedding:latest` | **4096** | 1.0000 | 3.54 s | 0.189 s | 5.86 s | **183.2 ms** |

两者输出**均已归一化**（L2 norm = 1.0），可直接使用 pgvector 的 `vector_cosine_ops`，无需自行归一化。

相对倍数：维度 **5.3×**、延迟 **19.3×**、模型体积 **17×**（274MB vs 4.7GB）。

## ⚠️ 反向硬证据（必须一并看，来自 spike 03）

spike 03 在同一批 EVAL_SET 上实测过两个编码器的**分流安全性**：

| 路径 | 编码器 | dangerous | F1（模糊误提交） |
|---|---|---|---|
| 3-way 路由 | nomic-embed-text (768d) | **3** ❌ | **1** ❌ |
| 3-way 路由 | qwen3-embedding (4096d) | 0 ✅ | 0 ✅ |

即：**nomic 768d 在「相似度阈值做安全判定」上不安全**——它区分不了模糊与确定（spike 02 同一根因：
相似度分数重叠）。**这不矛盾于本 spike 的选型，但严格约束了它的用途。**

## 结论（已定，`vector(768)`）

**MVP 唯一 embedding 索引列 = `nomic-embed-text`，`vector(768)`。**

1. **用途收敛**：embedding 只用于**检索召回 / 反向连接候选**，**不得用于任何安全判定**（双轨分流、
   弃权阈值）。双轨判定走 DecisionRouter（架构 §2 已定为主方案，spike 03 F1/F2 实测安全）。
2. **资源**：16GB 机器上需常驻 `qwen3.5:4b-mlx`(4.0GB) 做蒸馏；再常驻 4.7GB 编码器是沉重负担
   （274MB vs 4.7GB）。19× 延迟差在批量回填/重算场景是数量级差异。
3. **可逆路径（关键，降低本次决策的不可逆性）**：若日后发现中文检索质量不足，**加第二列
   `embedding_strong vector(4096)`** —— 加列是**增量**，不破坏既有 768d 索引，不必重建。
   真正不可逆的只有「先按 1024 落地再发现不符」这种情况，本 spike 正是为消除它。

## 限定与 open（禁止外推）

- **单次采样**：延迟未做多轮（网络/调度抖动未评估）；维度与归一化是确定性结果，不受采样影响。
- **未测中文检索质量**：本 spike 不评估召回质量。nomic 中文语义弱于 qwen3 是**合理预期但未实测**
  → 已登记为实施计划 §5 **R18**（P5 检索阶段用真实语料验证；不合格则走上面的加列路径）。
- **不覆盖多语言/长文本**：nomic 上下文 8192 token，长文档需切分，切分策略未定（属 P5 范围）。
