# Spike 11 — 跨源断言强制算子（解决 Spike 10 的 open 项）

> 状态：**已完成。9 tests passed；4B×3 与 1.5B×3 真实采样均已收口（§5）。核心结论：跨源综合是算子层问题、非模型规模——4B 稳定 3/3 实证；但 1.5B 无溢出收益，能力下限仍由模型决定。**
> 目标：验证「跨源综合失败是算子/提示层问题，不是模型规模问题」这一假设——
> 即在**不换更大模型**的前提下，靠算子层改造把跨源综合（cross-source synthesis）做到稳定达标。

## 1. 背景：Spike 10 留下的 open 项

Spike 10 的多采样分布（1.5B/4B 各 3 次）得到一个高置信结论：

- **换世代显著降低复述率**（1.5B 0.55–0.69 vs 4B 0.075–0.103，区间不重叠）。
- **跨源综合仍然不达标**：4B 3 次里仅 2 次通过，唯一一次失败恰好踩在「≥2 条跨源断言」门槛下；1.5B 仍 0/3。
- 该失败**与模型规模解耦**：它不是「4B 比 1.5B 强多少」的问题，而是 combine 算子*根本不强制*跨源综合——`_build_prompt` 只**软性**要求一个「global 层」，小模型自然退化成「一条来源一条 claim，从不真正综合」。

结论：跨源综合的缺口在**算子/提示层**，应改算子，而非再换更大模型。本 spike 就做这件事。

## 3. 算子设计：提示硬约束 + 单次补全回路

代码见 `cross_source_op.py`。两点改造，都在算子层，不碰模型：

### 3.1 提示层硬约束
主生成 prompt 第 3 条从「软性建议 global 层」升级为**硬约束**：

> 【硬约束】claims 中必须至少包含 `min_cross_source`(=2) 条**跨源综合断言**——每条 `evidence_ids` 含「≥2 个不同来源 id」，并明确说明这些来源之间是相互印证 / 冲突 / 互补 / 还是共同指向某个更高维模式。

### 3.2 算子补全回路（bounded，单次）
模型不总是遵守硬约束。所以主生成后算子**计算跨源 claim 数**：若 `< min_cross_source`，触发**一次**跨源补全调用（专门 prompt，要求只补缺失的跨源 claim，并指明来源间关系），把补生成的跨源 claim merge 进 artifact，再跑一次 citation enforcement。

- **单次、有界**，不无限循环；
- 补全 claim 同样过 `enforce_citations`（幻觉来源 id 会被过滤）；
- 补全若全部崩塌（citation 全丢失），保留主生成产物，不崩溃。

> 设计立场：这是「best-effort 强制」——多数情况下主生成即达标，不达标时一次性补齐。它把「跨源综合」从「靠模型自觉」变成「算子保证下限」。

## 4. 单测证据（9 tests passed，stub 注入，不依赖模型）

`test_enforcement.py` 用 stub 注入 LLM 函数，验证机制本身正确：

| 测试类 | 验证点 |
|---|---|
| `PromptLayerTests` | 主生成 prompt 与补全 prompt 都含硬约束措辞 |
| `CompletionLoopTests` | 主生成 0 跨源 → 补全触发 1 次且 `need` 正确、最终达标；主生成已达标 → 补全**不**触发；补全的幻觉 citation 被 enforce 过滤；补全全崩保留主产物 |
| `RubricGateTests` | `verdict.cross_source` 在 0/1/2 条跨源时分别 False/False/True（门槛逻辑正确） |

机制层面已证明：算子能在主生成不合作时把跨源综合补到 ≥2 条，且 citation 闸门仍生效。

## 5. 真实模型分布对比（4B 已回填）

控制变量就绪（`rerun11.py` / `multi_sample11.py` 复用 spike-10 的 corpus+rubric）。

### 5.1 4B：新算子 vs baseline（3×3 采样，multisample11.json）

| 指标 | baseline(旧算子 4B×3) | **新算子 4B×3** |
|---|---|---|
| 跨源 gate 通过 | 2/3（失败次踩 ncross=1） | **3/3** |
| `n_cross_source` 中位(区间) | 2 (1–2) | **2 (2–3)**，下限从 1 抬到 2 |
| `cross_source_rate` 中位 | 1.0（可被少发 claim 刷高） | 1.0（且有绝对数兜底） |
| 复述率中位 | 0.10 | 0.111（0.084–0.122，持平） |
| 补全回路触发 | —（旧算子无此机制） | **0/3**（主生成即满足硬约束） |

**结论【高置信】**：只换算子层、schema 与模型全冻结的前提下，4B 的跨源 gate 从 2/3 → **稳定 3/3**，且 `n_cross_source` 下限从 1 抬到 2—— spike 10 的「唯一一次失败踩门槛」被消除。**「跨源综合是算子/提示层问题、非模型规模」被实证。** 更强的信号：硬约束让模型在主生成就产出 2–3 条跨源断言，补全回路一次都没用到（成本零增加）。

### 5.2 1.5B：弱模型上的溢出收益（已回填：无）

| 指标 | 1.5B×3 baseline | **1.5B×3 新算子** |
|---|---|---|
| 跨源 gate 通过 | 0/3 | **0/3** |
| `n_cross_source` 中位(区间) | 0 (0–0) | **0 (0–0)** |
| 复述率中位 | 0.65 | 0.656（持平） |
| 补全回路触发 | —（旧算子无此机制） | **3/3 触发，但 3/3 结构化验证失败** |

**结论【高置信】**：算子改造对 1.5B **无溢出收益**。弱模型瓶颈是双重的：① 主生成无视硬约束提示（跨源仍 0）；② 补全回路虽然 bounded、安全（验证失败即丢弃、保留主产物），但 1.5B 连补全 prompt 的返回结构都不守（缺 `title/kind/claims` 顶层字段，`max_retries=0` 直接放弃）。**跨源综合能力的下限由模型结构化能力决定，算子只能保证「结构化能力够」的模型稳定达标**——这与 §5.1 的 4B 稳定 3/3 互为印证：4B 以上走算子保证，1.5B 不可用（复述率 0.65 也远不达标）。

## 6. 仍 open（诚实标注）

- **复述率**：本算子只解决「跨源综合」，不解决「单源 claim 复述」。1.5B 的复述率 0.55–0.69 仍需靠模型换代或蒸馏算子改善——这是另一个维度。
- **幻觉/忠实度**：rubric 字面不可测（见 spike-10 docstring 盲区），跨源 claim 是否真由所指来源支撑，仍需 LLM judge 或人工。
- **阈值**：`min_cross_source=2`、`VERBATIM_MAX` 等仍是占位，待人工标注样本校准。
- **成本**：补全回路在主生成不达标时多一次 LLM 调用（约 +1× 推理），需计入 MVP 延迟预算。
