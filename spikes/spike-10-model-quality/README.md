# Spike 10 · 强模型蒸馏/结合质量复测 + 质量口径定义（架构 §9 剩余项 ①）

> 状态：**四臂复跑完成 + 8 tests passed + 多次采样分布已出（1.5B/4B 各 3 次，见 §3.1）**
> **结论已升级为高置信**：同臂 3 次采样把「换世代降复述 / 跨源综合仍未解决 / 修重试非瓶颈」从中置信升为高置信
> 目标不是「换个模型看看好不好」，而是**让"达标"变成可判定的**：先有 rubric，再换模型，且把「策略贡献」与「模型贡献」分开。

## 1. 结论（按置信度排序）

1. **【高置信】质量口径已可判定**：复述率 / 拼接复述 overlap / 跨源率 / 引用命中 / 结构完整度五个维度可自动计算，不再是"看起来像摘要堆砌"。
2. **【高置信】换世代显著降低复述率**：1.5B combine 复述率中位数 0.649（区间 0.553–0.689）、overlap 0.656；Qwen3.5-4B 降到 0.10（0.075–0.103）、overlap 0.057。两模型区间**完全不重叠**，3 次采样复现（见 §3.1）。
3. **【高置信】跨源综合仍未解决（失败模式被复现）**：4B 3 次采样仅 2 次通过（2/3），唯一失败（ncross=1, rate=0.333）正好踩在「≥2 条跨源断言」门槛下；1.5B 3 次均 0 通过（ncross 0–1）。换模型**没有稳定**解决跨源综合——4B 仍有 1/3 概率产不出 ≥2 条跨源断言。
4. **【高置信】修重试策略不是质量瓶颈**：1.5B + resilient 重试 3 次采样 0/3 通过，与 legacy 0 通过一致，整段分布无改善；此前 B→C 改善来自模型而非重试。我上一轮把两者并列推荐，权重给错了。
5. **【高置信】9B 在这台 16GB 上不可用于迭代** → MVP 迭代模型定为 **`qwen3.5:4b-mlx`**（4B 在 16GB 上常驻 ~5.5GB 流畅、combine 通过率 2/3，远优于 1.5B 的 0/3，进一步坐实）。

## 3. ⚠️ 致命发现：采样噪声足以翻转结论（已用 3×3 分布收口）

**单次采样不可信**——同一臂（1.5B + 内置重试）两次运行：combine 复述率 0.678 → 0.105；跨源率 0.0(4 claim) → 1.0(1 claim)。这直接推翻了我先前"1.5B 跨源率恒为 0"的单次结论。

**指标漏洞（已修）**：比率可被"少发 claim"刷高——run2 只发 1 条 claim 引 2 源就得 rate=1.0 → rubric 改为同时要求绝对数量（`n_cross_source >= 2`）。

### 3.1 多次采样分布（1.5B / 4B 各 3 次，combine 算子，resilient 重试）

| 模型 | 采样 | verbatim(med / min–max) | overlap(med) | cross_rate(med / min–max) | n_cross(med / min–max) | citation(med) | pass |
|---|---|---|---|---|---|---|---|
| 1.5B | 3 | 0.649 / 0.553–0.689 | 0.656 | 0.0 / 0.0–0.2 | 0 / 0–1 | 1.0 | **0/3** |
| 4B  | 3 | 0.10 / 0.075–0.103 | 0.057 | 1.0 / 0.333–1.0 | 2 / 1–2 | 0.75 | **2/3** |

逐条升级（此前为"中置信"）：

- **换世代降复述 → 高置信**：1.5B 复述率 0.55–0.69 vs 4B 0.075–0.103，**区间完全不重叠**；overlap 0.656 vs 0.057。3 次采样复现，不再是单次噪声。
- **跨源综合仍未解决 → 高置信（失败模式被复现）**：4B 唯一失败（ncross=1）正好踩在 ≥2 门槛下，证明这是**随机失败**而非稳定通过——4B 仍有 1/3 概率产不出 ≥2 条跨源断言。
- **修重试非瓶颈 → 高置信**：1.5B + 修好重试仍 0/3，整段分布无改善；与 B→C 归因一致。
- ⚠️ **citation_hit 反向不说明 4B 更差**：4B 中位数 0.75（一次 0.5）低于 1.5B 的 1.0，但那是 1.5B 复述多、每条都贴源的产物，非真质量。

**结论**：模型代际能力鸿沟真实且巨大（1.5B 不可用，4B 可用但不稳）；跨源综合的剩余缺口是**算子/提示层**问题（强制 ≥2 条跨源断言），不是再换更大模型能解决的（9B 不可迭代）。

## 6. 质量 rubric：三个测量盲区（都记账）

1. **忠实度/幻觉无法字面测**：抽象 claim 本就该用源文本没有的词，「好抽象」与「无据编造」的字面重叠都低（实测：抄的 1.0/1.0；好抽象 0.18/0.12）→ 需 LLM judge 或人工，**不做门槛**。
2. **LCS 抓不住拼接式复述**：多段短语拼接的 claim LCS 不高但 3-gram 重叠极高（A 臂一条照抄 s2 的 claim `verbatim=0.48` 会误过 0.5 门槛）→ 增加 `overlap` 并列门槛（≤0.70）。
3. **比率可被少发 claim 刷高**：见 §3 → 增加绝对数量要求（≥2 条跨源 claim）。

门槛（**均为占位，需人工标注校准**）：`verbatim ≤ 0.50`、`overlap ≤ 0.70`、`cross_source ≥ 0.30 且 ≥2 条`、`structural_fit = 1.0`。

## 10. 环境坑（可复用）

1. `ollama pull` 直连 DNS 超时但代理可达 → `env HTTP_PROXY=...:7890 ollama pull`（**用 `env` 前缀，shell 赋值会被拦截**）。
2. `extra_body={"think": False, "options": {"num_ctx": 8192}}` 经 OpenAI 兼容层可传；MLX runner **默认已关 thinking**。
3. registry `tags/list` 端点 404，只能逐个探测 manifest；**并发过快会产生假阴性**，需加 sleep。
4. 16GB 机器上跑 ≥9B 前先 `docker stop` 无关容器并卸载模型。
