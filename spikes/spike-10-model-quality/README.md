# Spike 10 · 强模型蒸馏/结合质量复测 + 质量口径定义（架构 §9 剩余项 ①）

> 状态：**四臂复跑完成 + 8 tests passed**（重试策略，stub 客户端）
> **⚠️ 结论带强限定：单次采样噪声足以翻转结果，任何单点对比都不可信（见 §3）**
> 目标不是「换个模型看看好不好」，而是**让"达标"变成可判定的**：先有 rubric，再换模型，且把「策略贡献」与「模型贡献」分开。

## 1. 结论（按置信度排序）

1. **【高置信】质量口径已可判定**：复述率 / 拼接复述 overlap / 跨源率 / 引用命中 / 结构完整度五个维度可自动计算，不再是"看起来像摘要堆砌"。
2. **【中置信】换世代显著降低复述率**：1.5B 的 combine 复述率 0.56–0.72、overlap 0.56–0.77；Qwen3.5（4B/9B）降到 0.155–0.171 / 0.02–0.12。
3. **【高置信】跨源综合仍不达标**：所有臂的跨源 claim **绝对数只有 0–1 条**，未达「≥2 条跨源断言」门槛。换模型**没有**解决这个问题。
4. **【中置信】修重试策略不是质量瓶颈**：A→B（只换重试）零改善；B→C（只换模型）显著改善。我上一轮把两者并列推荐，权重给错了。
5. **【高置信】9B 在这台 16GB 上不可用于迭代** → MVP 迭代模型定为 **`qwen3.5:4b-mlx`**。

|---|---|---|---|---|---|---|---|---|---|
| A run1 | 1.5B + 内置重试 | 0.308 | 0.692 | 0.678 | 0.770 | 0.000 (0/4) | 1.000 | 1.00 | ✗ |
| B run1 | 1.5B + 修好重试 | 0.308 | 0.692 | 0.715 | 0.769 | 0.000 (0/4) | 1.000 | 0.75 | ✗ |

> **修正 rubric 后（跨源需 ≥2 条绝对数）没有任何一臂通过 cross_source 门槛**——这是比"9B 通过"更诚实也更严格的结论。

产物对照（蒸馏，同源 s1/s3/s5）：
- **1.5B**：「临时绕过会变成系统的长期负担，必须在服务端完成权限判断」← 拼接复述
- **4B**：「短期绕过将演变为长期系统负担」+「技术债显性化是可控权衡的关键机制」
- **9B**：「任何为追求速度而实施的临时架构妥协，若未被显性记录并绑定清理责任，其维护成本将呈指数级增长并最终反噬项目进度」

## 3. ⚠️ 致命发现：采样噪声足以翻转结论

同一臂（A：1.5B + 内置重试）两次运行：

| | run1 | run2 |
|---|---|---|
| combine 复述率 | 0.678 | **0.105** |
| 跨源率 | 0.000 (4 条 claim) | **1.000 (1 条 claim)** |

**单次采样的任何对比都不可信。** 这直接推翻了我先前基于单次采样下的"1.5B 跨源率恒为 0"结论。

**第三个指标漏洞（已修）**：比率可被"少发 claim"刷高——run2 只发 1 条 claim 引 2 个源，就得到 cross_source_rate=1.0。故 rubric 改为**同时要求绝对数量**（`n_cross_source >= 2`）。

**仍在进行**：`multi_sample.py` 对 1.5B / 4B 各跑 3 次取分布（耗时远超预期，因 16GB 上推理慢）。**在其完成前，本 spike 的模型对比结论应按"中置信"对待。**

## 5. 9B 在这台 16GB 上不可用于迭代（实测）

| 状态 | 数值 |
|---|---|
| 常驻 | 9.4GB（@16384）→ **10–12GB**，Ollama 自行降到 context 4096 |
| 系统空闲 | **9–10%** |
| swap | **16–20GB / 17–21GB（几乎满）**，Pageouts 3.8M |
| 单次蒸馏 | **4.7 分钟**；完整 C 臂 **23 分钟** |

缓解（停 PG + `keep_alive:0` + num_ctx 8192）能把空闲拉回 69%，一跑起来又掉回 10%。**硬件约束，不是配置问题。**

## 6. 质量 rubric：三个测量盲区（都记账）

1. **忠实度/幻觉无法字面测**：抽象 claim 本就该用源文本没有的词，「好抽象」与「无据编造」的字面重叠都低（实测：抄的 1.0/1.0；好抽象 0.18/0.12）→ 需 LLM judge 或人工，**不做门槛**。
2. **LCS 抓不住拼接式复述**：多段短语拼接的 claim LCS 不高但 3-gram 重叠极高（A 臂一条照抄 s2 的 claim `verbatim=0.48` 会误过 0.5 门槛）→ 增加 `overlap` 并列门槛（≤0.70）。
3. **比率可被少发 claim 刷高**：见 §3 → 增加绝对数量要求（≥2 条跨源 claim）。

门槛（**均为占位，需人工标注校准**）：`verbatim ≤ 0.50`、`overlap ≤ 0.70`、`cross_source ≥ 0.30 且 ≥2 条`、`structural_fit = 1.0`。

## 7. 重试策略修复（8 tests passed，stub 不依赖模型）

`llm_client.py`：接管重试，`max_retries=0` 让 Instructor 不追加；每轮**重建 messages**（原始 prompt + 一条有界提示），长度恒定。
`test_retry.py` 锁定：prompt 增长 ≤200 字符、每轮 messages 长度恒为 1、`max_retries=0`、错误提示有界。

## 8. 我自己的 bug（已修，记账）

## 9. 仍 open

- **多次采样分布**（进行中，见 §3）——在此之前模型对比结论只算中置信。
- **幻觉/忠实度**需 LLM judge 或人工。
- 阈值（0.50 / 0.70 / 0.30 / ≥2 条）为占位，需人工标注校准。
- **9B GGUF（6.55GB）+ num_ctx 8192 的常驻**未实测。
- **跨源综合本身**：换模型没解决，可能需要改算子（分步生成 / 显式"跨源断言"指令），而非换模型。

## 10. 环境坑（可复用）

1. `ollama pull` 直连 DNS 超时但代理可达 → `env HTTP_PROXY=...:7890 ollama pull`（**用 `env` 前缀，shell 赋值会被拦截**）。
2. `extra_body={"think": False, "options": {"num_ctx": 8192}}` 经 OpenAI 兼容层可传；MLX runner **默认已关 thinking**。
3. registry `tags/list` 端点 404，只能逐个探测 manifest；**并发过快会产生假阴性**，需加 sleep。
4. 16GB 机器上跑 ≥9B 前先 `docker stop` 无关容器并卸载模型。
