# 已捕获条目 = 单程票（28d 观察 → 到期即归档，永不回蒸馏）

Status: accepted (2026-10-31, zj 拍板)

spike 08 判定「已捕获 → ARCHIVE」，spike 09 判定「已捕获 → 28d」，两条被架构 §8 记为未决冲突。实为**两个不同问题被写成了同一句**：09 答「到期**前**多久看一次」（价值已沉淀 → 28d，把到期推到 0.9×28≈25.2 天），08 答「**已**到期怎么办」（价值已在元认知层 → 直接归档，不再蒸馏）。统一为：**已捕获 = 一张单程票：拉长观察（28d）→ 到期即 ARCHIVE，永不回到 DISTILL。**

## Considered Options

- **单程票（采纳）**：两条规则各管一端，不必互相推翻；语义可解释——价值已提炼的原始记录，既不需要频繁看，也不需要在到期时再提炼一次。
- **立即归档**（不等到期，`interval=NULL` 彻底退出调度）：最省注意力，但丢掉「claim 被撤销后原件回到动态轨」的路径，只能靠人工捞；且推翻 spike 08「只在到期才归档」的设计。
- **28d 且到期走 DISTILL**：与 spike 08 冲突，会导致同一条目被重复蒸馏。

## Consequences

- 两条边界与本决策同等重要，缺一不可：
  1. **撤销回退**：承载它的 claim/artifact 被 `produced_by` 级联撤销后，「已捕获」状态消失 → 按未捕获基线重算（有连接 14d / 孤儿 7d），且**必须写 `interval_adjustment` 留痕**，禁止静默变化——否则「撤销」在调度层不可见。
  2. **`self_loop` 压过已捕获**：项目躬身入局的条目即便已被提炼，原件仍在变（3d > 28d）。原 spike 09 的 L1 表把「已捕获 28d」排在 `self_loop` 3d 之前，而 L2 优先级表把 `self_loop`(2) 排在已捕获(0) 之前，**两处顺序相反**——本决策一并修掉（L1 表已改序）。到期终局仍走 ARCHIVE。
- 影响实现：P4.5 从「规则待统一」变为具体任务（28d → ARCHIVE 永不 DISTILL + 撤销回退 + L1 改序）。
